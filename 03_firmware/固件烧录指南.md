### 烧录

```shell
cd /d/ARMGCCTool/WirelessDebuggingtool/firmware-src/wireless-esp8266-dap
/d/ARMGCCTool/WirelessDebuggingtool/pyenv/Scripts/esptool.exe --chip esp32s3 --port COM18 --baud 921600 write-flash --flash-mode dio --flash-size 16MB --flash-freq 80m 0x0 build/bootloader/bootloader.bin 0x8000 build/partition_table/partition-table.bin 0x10000 build/wireless_esp_dap.bin
```

> `--flash-size` 用 `16MB` 而不是 `detect`。用 `detect` 会让 esptool 在烧录时把 bootloader 头的容量字节从 `0x1f`(2MB)改成 `0x4f`(16MB),而这个头被镜像末尾的 SHA-256 覆盖、esptool 不会重算——结果每次启动都报 `SHA-256 comparison failed`。

- ⚠️ **烧完松开 BOOT、单独按一下 RST 才会跑程序**;BOOT 按住/卡住 = 芯片一直停在下载模式(USB 枚举 PID_1001),表现为设备彻底失联
- **烧录只用 native USB(USB-Serial-JTAG,COM18)**;CH343 那个口插着会把芯片拽进下载模式
- 启动/WiFi 日志:COM18(USB-Serial-JTAG)可看实况(如 `Disconnect reason: 201` = NO_AP_FOUND)

   - `wireless_esp_dap_full.bin`(合并整包)
   - `wireless_esp_dap_app.bin` + `bootloader\bootloader.bin` + `partition_table\partition-table.bin`(三件套)
2. **flash_download_tool 烧录**(GUI 已就位:`D:\ARMGCCTool\WirelessDebuggingtool\flash_download_tool\flash_download_tool_3.9.9_R2.exe`):
   - 芯片类型选 **ESP32-S3** → 加载方式二选一:
     - 整包:`wireless_esp_dap_full.bin` @ **`0x0`**(推荐)
     - 三件套:`bootloader.bin` @ `0x0` + `partition-table.bin` @ `0x8000` + `wireless_esp_dap_app.bin` @ `0x10000`
   - 选 COM 口 → START(烧不进按住 BOOT 再上电);若整包烧完不启动,改用三件套方式
3. **esptool 命令行**(venv 已装 v5.6.0):
   ```shell
   D:\ARMGCCTool\WirelessDebuggingtool\pyenv\Scripts\esptool.exe --chip esp32s3 --port COM5 --baud 921600 write_flash 0x0 wireless_esp_dap_full.bin
   ```
4. 烧完复位,设备按固件内置的 WiFi 列表联网(**已核实源码默认值**,预编译与源码一致):
   - 默认以 STA 模式连接 SSID **`OTA` 或 `DAP`**(密码均为 `12345678`);**没有 AP 模式**(kerms 分支才有 AP)
   - 最简单的首跑方式:**PC 开 Windows 移动热点**,名称改为 `DAP`、密码 `12345678`——代码预留的静态 IP 网段 `192.168.137.x` 正是 Windows 移动热点的默认网段,这就是官方预期的用法
   - 想连家里路由器:走方式二源码编译,把 SSID/密码写进 `wifi_configuration.h`(支持配置多个候选 AP)
5. 验证在线:PC 与设备同网段后 `ping dap.local`(源码默认 `USE_MDNS=1`,主机名 `dap`)

## 启动报 `SHA-256 comparison failed`(已修,记录根因)

症状:每次上电,串口打出三行,然后照样正常启动。

```
SHA-256 comparison failed:
Calculated: fa2c47c6...
Expected:   23b1fbe5...
Attempting to boot anyway...
```

**不影响功能**,所以很容易被当成噪音忽略,但它意味着镜像完整性校验永久失效,而且日志在每次启动都说谎。这两行固定值,就是定位的入口。

### 根因

ESP32-S3 的 bootloader 镜像末尾带 32 字节 SHA-256,覆盖自己前面的全部内容,**包括开头 8 字节的镜像头**。镜像头第 3 字节是 `flash_size<<4 | flash_freq`。

工程原来的配置是 Kconfig 默认的 `CONFIG_ESPTOOLPY_FLASHSIZE="2MB"`(ESP8266 时代遗留的默认值),所以编译出来的镜像头是 `0x1f` = 2MB@80MHz。但板子是 16MB,而 `CONFIG_ESPTOOLPY_FLASHSIZE_DETECT=y` 让 esptool 在烧录前探测真实容量并改写这个字节:

```python
# esptool.py: _update_image_flash_params()
flash_params = struct.pack(b'BB', flash_mode, flash_size + flash_freq)
if flash_params != image[2:4]:
    print('Flash params set to 0x%04x' % ...)
    image = image[0:2] + flash_params + image[4:]   # 只改头,不重算末尾 SHA-256
```

于是 flash 里躺着一个"身体被改过、末尾哈希还是旧值"的镜像,ROM 一比就不符。

### 验证方法(不猜,算出来)

拿本地 `build/bootloader/bootloader.bin`,枚举把第 3 字节改成各种值后的 SHA-256,看哪个等于日志里的 `Calculated`:

```python
import hashlib
b = bytearray(open("build/bootloader/bootloader.bin","rb").read())
body = bytes(b[:-32])
for off in range(8):
    for v in range(256):
        if v == body[off]: continue
        c = bytearray(body); c[off] = v
        if hashlib.sha256(bytes(c)).hexdigest() == "fa2c47c6..."[:64]:
            print("offset", off, "0x%02x -> 0x%02x" % (body[off], v))
```

结果唯一命中:**offset 3,`0x1f` → `0x4f`**,也就是 2MB → 16MB。`Expected` 则正好等于未改动文件的哈希。到此链条闭合,不需要再上板。

### 修复

`sdkconfig` 与 `sdkconfig.defaults.esp32s3` 都改成:

```
CONFIG_ESPTOOLPY_FLASHSIZE_16MB=y
CONFIG_ESPTOOLPY_FLASHSIZE="16MB"
# CONFIG_ESPTOOLPY_FLASHSIZE_DETECT is not set
```

镜像头从一开始就写对,esptool 的改写变成空操作,末尾哈希自然自洽。验收看两点:

1. 本地 `build/bootloader/bootloader.bin` 头部第 3 字节 = `0x4f`,且 `sha256(body) == 末尾32字节`
2. `esptool verify_flash` 三个区段全部 `verify OK (digest matched)`——这条同时证明 esptool 没有改写任何字节

> **移植提醒**:换到别的板子(比如 N8R8 = 8MB)时,这个值必须跟着改。**不要图省事把 DETECT 打开**——它会静默改写一个已被哈希覆盖的头,而不是报错。宁可写死一个可能不对的值,也不要让校验静默失效。

## 常见问题

- **烧录失败 / 连不上 COM 口**:C3 SuperMini 类小板注意按住 BOOT 再插 USB 进下载模式
- **ping 不通 dap.local**:换设备 IP 直连;确认路由器未开 AP 隔离
- **flash 下载报错**:确认电源充足;部分开发板 USB 供电不足会导致 WiFi 发射时掉电重启
- **`SHA-256 comparison failed`**:见上一节。根因是 flash 容量配置与实物不符 + `FLASHSIZE_DETECT` 改写哈希覆盖区
