# 方案审查(2026-10-25)

> 审查对象:路线 A 全套文档(原型验证计划 / 固件烧录指南 / 接线参考 / PC 端环境搭建)。
> 结论:**方案成立,可执行**;发现 4 个 P1 问题已全部修正,3 个 P2 风险已补入文档。

## P1 发现(影响首跑成败,已修正)

1. **首配网流程缺失(最重要)**:预编译固件不会连家里路由器——已核实源码 `wifi_configuration.h`:默认 STA 模式连 SSID **`OTA`/`DAP`(密码 `12345678`)**,且**没有 AP 模式**(kerms 分支才有)。正确首跑姿势 = PC 开 Windows 移动热点改名 `DAP`(代码预留的静态 IP 网段 `192.168.137.x` 正是 Windows 热点默认网段,官方预期用法),或源码编译写入自家 WiFi。→ 已补入烧录指南与验证计划。
2. **usbip-win 命令已过时**:0.3.3 起 `attach_ude`/`install_ude` 已删除,统一为 `attach`/`install`;windowsair README 写的是旧用法。且 v0.3.6-dev 起 vhci 驱动已微软 attestation 签名,**不再需要测试签名模式**(比原预想更省事)。→ 已重写 PC 端文档第 3 节。
3. **AP 模式测试项不成立**:windowsair 原版固件无 AP 模式,测试矩阵原"AP 模式顺带测试"无法执行。→ 改为"距离测试",并注明需要 AP 时切 kerms 固件。
4. **Keil 驱动选择步骤不准**:elaphureLink 是独立 µVision 驱动(GUI 内先装驱动),Keil Debug 下拉框选 **elaphureLink**,不是自带的 CMSIS-DAP 选项;且不支持 Keil Studio。→ 已修正。

## P2 风险(已补入文档,测试时留意)

1. **双板 mDNS 冲突**:两块板主机名都是 `dap.local`,一次测一块或用 IP 直连。
2. **5V 逻辑目标风险**:ESP GPIO 非 5V 容忍,原型阶段限定 3.3V 逻辑目标板;电平转换留给 PCB 阶段。
3. **ESP32/RISC-V 目标走 JTAG**:与 SWD 四线不同(需 TDI/TDO,引脚表已补);先聚焦 Cortex-M 主线。
4. 源码默认 `USE_OTA=0`、`USE_UART_BRIDGE=0`:OTA/串口透传默认关,源码编译时需自行开宏。
5. ESP-IDF v4.4.2 对 S3:README 明确标注的是 ESP32/C3,编译 S3 时如有问题查 README 更新(低风险)。
