## 2. 架构:一条命令通道,两个运行模式

```
┌──────────────┐   USB 线 (COM18, USB-Serial-JTAG)   ┌─────────────────┐
│  PC 工具     │ ────────── @命令 / @响应 ─────────> │  ESP32-S3       │
│  (Python GUI)│                                     │                 │
└──────────────┘                                     │  dap_cmd 解析   │
                                                     │  dap_config(NVS)│
        STA 模式(日常)          AP 模式(无路由器)   │  wifi_handle    │
   PC ──WiFi──> 路由器 <──WiFi── DAP          PC ──WiFi──> DAP
        └── TCP 3240 / 1234 ──┘                    └── TCP 3240 / 1234 ──┘
                                                      (192.168.4.1)
```

### 2.1 为什么命令通道必须走 USB

配网要解决的正是"板子还没上网"的状态,此时没有 IP 可连,所以命令通道只能是**物理链路**:USB-Serial-JTAG(COM18)。这也是烧录用的同一个口,插线即用,零额外硬件。

> 顺带的好处:STA 连不上时,PC 插 USB 就能发 `@MODE AP` 救场——比按键方案更适合"给同事用"(不需要教他长按几秒)。

### 2.2 关键约束:纯 AP 模式扫不了频

IDF 官方文档 `docs/en/api-guides/wifi.rst:423` 原文:**"esp_wifi_scan_start() API is supported only in Station or Station+AP mode"**。

这条直接否定"AP 模式下让用户扫 WiFi 列表"的做法。因此:

- **配网在 STA 模式下进行**(STA 已启动、未连接,可前台扫描)
- **AP 模式不承担配网职责**,只承担"没有路由器时给 PC 一个接入点"这一个职责
- 配网时板子并不需要开热点——热点在配网流程里是多余的

### 2.3 AP 模式的定位收窄

| | 第一版设想 | 本版 |
| --- | --- | --- |
| 谁负责配网 | AP + 浏览器 | **PC 工具 + USB 命令** |
| AP 的作用 | 配网入口 + 兜底 | **仅"无路由器"时的接入点** |
| 何时进入 AP | 自动/按键/浏览器 | **只有 `@MODE AP` 命令** |
| 板端 HTML/HTTP 服务 | 要写 400-500 行 | **零** |

### 3.3 USB 日志与命令共存(本项目最关键的技术风险)

#### 先厘清:板上有三条独立通路,别混

| 通路 | 物理引脚 | 当前配置 | 用途 |
| --- | --- | --- | --- |
| **UART0** | GPIO43(TX)/44(RX),需外接 USB-TTL | **主 console**(`ESP_CONSOLE_UART_DEFAULT=y`) | 应用日志主出口 |
| **USB-Serial/JTAG** | GPIO19(D-)/20(D+),板上 native USB = **COM18** | **次 console**(`ESP_CONSOLE_SECONDARY_USB_SERIAL_JTAG=y`) | 日志镜像 + 烧录口 |
| **UART1** | GPIO17(TX)/18(RX) | `uart_bridge.c` 串口桥 | 连目标板串口(TCP:1234) |

三者硬件独立,互不占用。串口桥(17/18)与本次改造无关,不受影响。

#### 关键前提:次 console 模式**收不到数据**

IDF Kconfig(`esp_system/Kconfig:244-257`)对 `ESP_CONSOLE_SECONDARY_USB_SERIAL_JTAG` 的原文:

> This secondary option supports output through other specific port like USB_SERIAL_JTAG when UART0 port as a primary is selected but not connected. This secondary output currently **only supports non-blocking mode without using REPL**. If you want **blocking mode with REPL or input through this secondary port, please change the primary config to this port**.

即:当前配置下 **COM18 是单向的**——能看日志,**收不到任何命令**。`esp_console_new_repl_usb_serial_jtag()` 也被 `#if CONFIG_ESP_CONSOLE_USB_SERIAL_JTAG`(`esp_console.h:351`)挡在编译外,不存在。

> 2026-10-28 修正:此前认为"装驱动 + 切 vfs 即可收发"**不成立**,光装驱动不够,必须先改 console 主通道。

#### 正确做法(三步,顺序不能反)

1. **把主 console 切到 USB-Serial/JTAG**(menuconfig 或直接改 sdkconfig):
   ```
   # CONFIG_ESP_CONSOLE_UART_DEFAULT is not set
   CONFIG_ESP_CONSOLE_USB_SERIAL_JTAG=y
   ```
   代价:UART0(43/44)不再有日志输出——当前未接外部 USB-TTL,无实际损失。
   不影响:COM18 烧录(esptool 走 ROM downloader,与 console 配置无关)、UART1 串口桥。
2. `usb_serial_jtag_driver_install()` 装驱动 + `esp_vfs_usb_serial_jtag_use_driver()` 把 vfs 切到驱动路径(`vfs_usb_serial_jtag.c:419`)。
3. 日志继续经 vfs 写出,命令从驱动环形缓冲读入(`usb_serial_jtag_read_bytes`)。

#### 残余风险与缓解

- **ROM 控制台直写外设**:`esp_rom_printf` 绕过 vfs,可能与驱动 TX 在字节级交错 → 协议行统一以 `@` 开头,PC 工具只认 `@` 行,日志正文当噪声丢弃。
- **切换后旧路径失效**:改主 console 后需 `build.bat fullclean`(sdkconfig 变更),且验证 UART0 静默、COM18 全双工。
- **这一条必须在 P1 第一步验证**(G0 门),不通过则整个命令通道方案要重新设计(备选:走 UART0 外接 USB-TTL,但违背"插一根 USB 线即可配网"的初衷)。

## 4. 命令协议(线格式)

ASCII 文本行,`\n` 结尾,容忍 `\r`。字段一律 **URL 百分号编码**(SSID 可能含空格/中文/`|`/`&`)。

- PC → 板:`@命令 参数...`
- 板 → PC:`@OK ...` / `@ERR <码> <说明>` / `@DATA ...`(可多条)/ `@EVT ...`(异步)
- 板端 IDF 日志不带 `@`,PC 侧直接丢弃

| 命令 | 参数 | 成功响应 | 说明 |
| --- | --- | --- | --- |
| `@PING` | — | `@OK pong fw=0.6.0 mac=A7:04:15:04:FC mode=STA` | 探测/识别设备 |
| `@STATUS` | — | `@OK mode=STA ssid=MyWiFi%2F2 ip=192.168.7.125 rssi=-52 ch=6` | 当前状态 |
| `@SCAN` | `[&ms=3000]` | 多条 `@DATA ssid=..&rssi=..&auth=..&ch=..` + `@OK scan count=7` | **仅 STA 模式**;AP 模式下返回 `@ERR 409 MODE_AP` |
| `@CONNECT` | `ssid=<enc>&pass=<enc>` | `@OK connected ip=192.168.7.125 rssi=-52` | 失败:`@ERR 201 NO_AP_FOUND` / `@ERR 202 AUTH_FAIL` / `@ERR 204 HANDSHAKE_TIMEOUT` / `@ERR 408 TIMEOUT` |
| `@MODE` | `STA` \| `AP` | `@OK mode=AP ip=192.168.4.1` | **唯一**的模式切换入口(C2) |
| `@LED` | `[pct]` | 查询 `@OK led pct=4`;设置 `@OK led pct=2 saved` | 不带参数=查询;`1..100`=设置并写 NVS。越界 `@ERR 400 pct_out_of_range_1_100` |
| `@LIST` | — | 多条 `@DATA idx=0&ssid=...&pass=***` + `@OK count=1` | 已保存凭据(密码打码) |
| `@DEL` | `idx=N` | `@OK` | 删除单条 |
| `@PRIO` | `idx=N` \| `ssid=<enc>` | `@OK prioritized ssid=MyWiFi idx=0` | 把某条置顶为**开机首选**;**稳定移动**(其余相对顺序不变)。`idx=0` 时幂等直接回 OK。找不到 SSID → `@ERR 404 ssid_not_in_list`;无参数 → `@ERR 400 usage` |
| `@FACTORY` | — | `@OK rebooting` | 擦 NVS 后重启 |
| `@REBOOT` | — | `@OK rebooting` | |

**超时约定**:`@SCAN` 默认 3s;`@CONNECT` 最长 20s(PC 侧等 25s);其余 < 1s。

**并发约定**:命令串行处理,单任务;`@CONNECT` 执行期间拒绝其他命令(`@ERR 423 BUSY`),但 `@PING` 例外。

## 5. 模式与状态机

### 5.1 两个模式

| 模式 | 触发 | WiFi 形态 | 地址 | 用途 |
| --- | --- | --- | --- | --- |
| **STA**(默认,日常) | 上电默认 / `@MODE STA` | `WIFI_MODE_STA`,按 NVS 列表轮询 | 路由器 DHCP | 与现状完全一致 |
| **AP** | **仅** `@MODE AP` | `WIFI_MODE_AP`,SSID `DAP-<MAC后4位>`,密码固定 | 板 192.168.4.1,PC 由板 DHCP 分配 | 没有路由器时给 PC 一个接入点 |

- **没有自动切换**。STA 连不上就一直按列表重试(C2)。
- 模式偏好写入 NVS,重启后保持上次模式。
- AP 模式下 3240(usbip/elaphureLink)与 1234(串口桥)照常可用 → **无路由器也能无线调试**。
- AP 模式无外网,PC 连上后上不了网——调试工具可以接受,文档写明。

### 5.2 STA 模式状态机(改动很小)

```
上电 → 读 NVS 凭据 ──> 逐条尝试(每条 10s)
                        ├─ 拿到 IP → 正常运行 ──(掉线)──> 回到逐条尝试
                        └─ 整轮失败 → 等 5s 再整轮重试(永不停,也不开热点)
手动 @CONNECT(来自 PC)──> 暂停自动轮询,单独试目标 AP
                        ├─ 成功 → 存入 NVS,恢复自动轮询
                        └─ 失败 → 上报原因码,恢复自动轮询
```

只有两处实质改动:①列表来自 NVS 而非编译期常量;②加 `manual_connect` 标志位,在此期间抑制自动轮转,并记录 `last_disconnect_reason` 供上报。

**修掉一个竞态(实测才发现,纸面推演不会碰到)**

手动连接时我们主动调 `esp_wifi_disconnect()` 断开旧连接,但该动作**同样会触发 `STA_DISCONNECTED` 回调**——回调里判定 `s_manual==true` 就当成"目标 AP 连接失败",把标志清掉并置 `done`。随后 `esp_wifi_connect()` 撞上已结束的状态,返回 `ESP_ERR_WIFI_CONN`。实测现象:**所有 `@CONNECT` 都报 `@ERR 500 ESP_ERR_WIFI_CONN`,连正确凭据也一样**。

修法:新增 `s_manual_switching` 标志,在主动 `disconnect` 前置位、`esp_wifi_connect()` 之后清除;回调见到该标志即忽略这次断连。另外 `esp_wifi_disconnect()` 后需让出 200ms,否则紧接着 `set_config`/`connect` 可能直接失败(实测返回 `ESP_ERR_NO_MEM`)。

**真机才暴露的固件缺陷(4 个,都已修复)**:

| 缺陷 | 现象 | 根因与修法 |
| --- | --- | --- |
| **命令 TX 环缓冲死锁** | 烧录后能用几秒,之后 `@PING` 永远写不进去(主机侧 `WriteFile` 永久挂起) | IDF 4.4 的 USJ 有两条 TX 路径抢同一个硬件 FIFO:日志走 VFS 直写 FIFO 且满了就丢字节,命令走 `usb_serial_jtag_write_bytes()` 写 ring buffer 靠 `SERIAL_IN_EMPTY` 中断排空。日志一多 FIFO 常满 → ISR 拿不到可写时机 → ring buffer 永远排不空 → `xRingbufferSend` 超时静默丢数据。**修法:`cmd_write` 也改走 `fwrite(stdout)`**,和日志共用一条 VFS 路径 |
| **`@SCAN` 在连接中必失败** | `@ERR 500 ESP_FAIL`,日志写 `sta_scan: STA is connecting, scan are not allowed!`;5 次仅 1 次成功 | IDF 禁止 STA connecting 状态下扫描,而自动轮转让板子几乎永远在 connecting。判据还不能用 `esp_wifi_sta_get_ap_info()`(连接中会返回上一次关联的残留记录)。**修法:扫描前无条件 `esp_wifi_disconnect()` + 延时 300ms**,扫完无条件 `esp_wifi_connect()` 恢复轮转;新增 `s_scanning` 标志让断连回调忽略这次主动断开(否则会白推一次 SSID 游标) |
| **`@CONNECT` 首次必报 `ESP_ERR_WIFI_CONN`** | 正确凭据也失败;紧接着的连接尝试报 201 | 扫描末尾刚调过 `esp_wifi_connect()` 恢复轮转,立刻 `esp_wifi_disconnect()` 会撞上驱动正在处理的状态。**修法:断开后轮询 `sta_get_ap_info` 确认驱动落定再 `set_config`;`connect` 遇 `ESP_ERR_WIFI_CONN` 等 300ms 重试一次** |
| **版本号没跟上** | 板上固件功能是 P2,`@PING` 却一直报 `fw=0.5.0` | `dap_version.h` 建文件时写了 0.5.0,后续 P1/P2 都没升。现场排障时 `fw=` 字段本应是固件身份,结果毫无意义。**修法:升到 0.7.0**(与文件头注释里的版本规则一致) |

> **这一轮的教训**:65 项注入式自测(假设备)全绿,但真机一插上去四个缺陷全暴露。假设备模拟的是**我自己理解的行为**,理解错了它也跟着错;真机测的是**硬件和 IDF 的真实行为**。后续每轮改动都要过一遍真机,不能只看自测。

**设计上刻意做的三个决定**:
1. **解析用锚定正则而非按 `&` 切分**。固件回显 SSID 不打百分号编码(`dap_cmd.c` 里 `"ssid=%s"`),SSID 含空格、`&`、`=` 时会撕开字段。工具侧用 `ssid=(.*)&rssi=` 这类锚定后缀的正则还原,不依赖固件改。
2. **15 / 202 / 204 统一按"密码或加密方式不匹配"解释**。IDF 对 WPA2 密码错误报的是 15(`4WAY_HANDSHAKE_TIMEOUT`)而不是 202(`AUTH_FAIL`),这条实测结论已固化进 `ERR_INFO`。
3. **只对幂等命令重试**。`@PING/@STATUS/@SCAN/@LIST` 超时会重发(最多 3 次),`@CONNECT` 绝不盲重试——板子可能已经在连,重发会撞 423。本地端口故障(`port_closed`/`write_failed`)不重试。

**P3 验收**:✅ 已通过。插上 USB 到连上 WiFi 全程只用 GUI,不碰命令行(2026-10-28 真机实测)。

**过程中踩到并修掉的构建问题**:

## 8. 风险

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| **USJ 日志与命令字节交错** | 命令解析失败 | P1-1 设 G0 门先验证;协议用 `@` 前缀过滤;必要时降日志等级 |
| ROM 控制台绕过 vfs | 偶发乱码 | 同上;PC 侧容错(重发机制:同一命令 3 次无响应则报错) |
| 纯 AP 模式不能扫描 | 设计已规避 | 配网固定在 STA 模式;AP 模式 `@SCAN` 明确报错 |
| AP 模式 PC 无外网 | 用户困惑 | 文档写明;GUI 在切 AP 时弹提示 |
| STA 一直连不上且用户不知能切 AP | 以为设备坏了 | GUI 在"连不上"时主动提示"可切到 AP 模式";`@STATUS` 显示重试状态 |
| NVS 写入寿命 | 长期反复配网 | 只在保存时写,非运行时写;24KB 分区足够 |
| 多台并存 | SSID/mDNS 冲突 | AP SSID 带 MAC 后缀;mDNS 主机名同样带后缀(顺带解决老风险) |

## 9. 待确认(只剩 4 项,都有默认值)

| # | 决策点 | 选项 | 默认建议 |
| --- | --- | --- | --- |
| E1 | 命令通道除 USB 外,是否也开一个 TCP 命令口(联网后可远程切模式) | ①只 USB ②USB + TCP(如 3239) | **①只 USB**。配网场景 USB 必在;TCP 命令口增加攻击面,后置 |
| E2 | 是否保留编译期 SSID 列表作出厂默认 | ①保留(现有 MyWiFi、DAP、OTA)②清空,强制首次配网 | **①保留**:你自己的板子刷完直接上家网,别人的板子第一次会失败然后插 USB 配网 |
| E3 | AP 热点参数 | SSID `DAP-<MAC4>`,密码 `12345678`,信道 6,最多 4 客户端 | 按此执行;密码可通过命令改 |
| E4 | PC 工具形态 | ①Python + tkinter 单文件 ②打包成 exe(PyInstaller) | **①先单文件**,发布时再决定是否打包 exe |
