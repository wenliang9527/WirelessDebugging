# 现有方案调研

> 调研日期:2026-10-25。结论速览见文末表格,详细选型讨论见 [方案对比与选型.md](方案对比与选型.md)。

## 一、开源方案

### 1. windowsair/wireless-esp8266-dap ⭐ 主流方案

- 仓库:https://github.com/windowsair/wireless-esp8266-dap (MIT,2020 年起,660+ stars)
- 一句话:**单颗 ESP 芯片**实现无线 CMSIS-DAP,通过 **USBIP 协议**让 PC 把它识别为"插在本机上的 USB 调试器"
- 芯片支持:ESP8266/8285、ESP32、ESP32-C3、ESP32-S3
- 调试接口:SWD + JTAG;USB 侧:USB-HID / WCID & WinUSB(默认)
- **免 USBIP 的直连路线(重要)**:
  - [elaphureLink](https://github.com/windowsair/elaphureLink):Keil 插件,Keil 直接走 TCP 连接设备,**无需 usbip、无需驱动**
  - [openocd-elaphurelink](https://github.com/windowsair/openocd-elaphurelink):带补丁的 OpenOCD,同样直连 TCP 免 USBIP
  - [elaphure-dap.js](https://github.com/windowsair/elaphure-dap.js):浏览器网页直接给 Cortex-M 烧固件
- 附加功能:UART TCP 透传(无线串口监视)、mDNS(`dap.local`)、网页 OTA 升级
- 速度策略:ESP8266 纯 IO 上限约 2 MHz;ESP32 系列在时钟 ≥10 MHz 时启用 **40 MHz SPI 加速**;作者明确"最大瓶颈仍是 TCP 连接速度"
- 现实参考:5 m 距离、100 KB hex 的擦除+下载可正常完成;USB-HID 模式单 URB 255 字节(~1 MB/s 带宽上限)
- 已知坑:对网络环境敏感(局域网广播风暴会让 ESP8266 几乎瘫痪,如 DropBox LAN Sync、部分网卡 AP 性能差);usbip-win 驱动在 Win11 上需要装测试签名驱动
- 生态:OpenOCD、pyOCD、Keil MDK 均可用;仓库带 `circuit/` 参考硬件设计

### 2. kerms/wireless-esp32-tools ⭐ windowsair 的现代化分支

- 仓库:https://github.com/kerms/wireless-esp32-tools (Apache-2.0,2023 年起,仍在活跃开发)
- 架构与 windowsair 相同(USBIP + CMSIS-DAP),但只支持 ESP32/C3/S3(砍掉了老旧的 ESP8266),代码更新、支持多 AP 配置
- 默认自带 AP 模式(SSID `无线DAP`),UART TCP 桥固定端口 1234
- 同样支持 elaphureLink 全家桶

### 3. bkuschak/cmsis_dap_tcp_esp32 — 纯 TCP 路线

- 仓库:https://github.com/bkuschak/cmsis_dap_tcp_esp32
- 思路:固件实现 **CMSIS-DAP over TCP**,配合带 `cmsis-dap-tcp` 后端的 OpenOCD 直连,**彻底不碰 USB/USBIP**
- 优点:无驱动问题、跨平台最干净;缺点:只能配特定 OpenOCD 后端,Keil 等无法直接用,生态小

### 4. masbc666/ESP32S3_Wireless_CMSIS_DAP — 双板方案

- 仓库:https://github.com/masbc666/ESP32S3_Wireless_CMSIS_DAP
- 用两块 ESP32-S3:一块插 PC 上枚举成"真 USB CMSIS-DAP",另一块接目标板,中间 WiFi 桥接
- 优点:PC 侧永远是真 USB 设备,兼容性最好;缺点:两块板、成本翻倍、要给 PC 侧供电插线(只省了 USB 到目标板这段线)

### 5. 其他相关

- Espressif 官方组件 `esp_dap`(ESP-IDF component registry):官方 CMSIS-DAP 实现,可自组 TCP/USB 传输,适合自研参考
- RP2040/Pico W:官方 [raspberrypi/debugprobe](https://github.com/raspberrypi/debugprobe) 是有线 CMSIS-DAP;**没有成熟的 Pico W 无线方案**,Pico 路线不适合本项目
- EZ32Inc/esp32jtag_firmware:ESP32-S3 一体化 JTAG/SWD + 16 通道逻辑分析仪,可作为功能参考

## 二、商用方案(性能基准参照)

### SEGGER J-Link WiFi

- 售价 **$1,380(约 ¥1 万)**:https://shop-us.segger.com/product/j-link-wifi-8-14-28
- SWD/JTAG 最高 15 MHz,下载到 RAM 1.0 MiB/s,支持全部 J-Link 软件生态(Ozone、J-Flash、RTT、GDB Server)
- 同厂还有 J-Link PRO(以太网)/ J-Link Remote Server(可跨网段远程调试)
- 定位:工业级、稳定、快 —— 也是我们开源方案的性能"天花板"参照

### 结论

商用无线调试器存在但极贵;开源方案以 **ESP 系 + CMSIS-DAP** 为事实标准,成熟度和社区规模都集中在 windowsair/wireless-esp8266-dap 及其分支上。

## 三、技术要点(所有无线 DAP 共有)

1. **协议栈层次**:`IDE → (USB/驱动层) → CMSIS-DAP 命令 → WiFi 传输 → 设备 GPIO/SPI 翻转 SWD 波形 → 目标芯片`
2. **两大传输架构**:
   - **USBIP 虚拟 USB**:固件模拟 USB 设备,PC 用 usbip-win 挂载 → 所有 IDE 免改动,但 PC 端要装驱动
   - **直连 TCP(elaphureLink / cmsis-dap-tcp)**:IDE 侧装插件或用补丁版 OpenOCD → 免驱动,但每个工具要有对应支持
3. **速度瓶颈排序**:TCP 往返延迟 > SWD 时钟频率 > USB 包大小限制
4. **稳定性**:对局域网质量敏感,组播/广播风暴、AP 性能差都会导致掉线或变慢

## 四、结论速览

| 方案 | 架构 | PC 驱动 | IDE 兼容 | 成熟度 | 成本 |
| --- | --- | --- | --- | --- | --- |
| windowsair/wireless-esp8266-dap | USBIP(或 elaphureLink 直连) | usbip-win 或 elaphureLink | Keil/OpenOCD/pyOCD 全支持 | 高(4年+,生态最全) | ESP32-C3 约 ¥10 |
| kerms/wireless-esp32-tools | 同上(现代化分支) | 同上 | 同上 | 中高(活跃开发) | 同上 |
| bkuschak/cmsis_dap_tcp_esp32 | 纯 TCP | 无 | 仅特定 OpenOCD | 低(个人项目) | 同上 |
| 双板 ESP32-S3 桥 | 真 USB + WiFi 桥 | 无 | 全支持 | 低 | 两块 S3 |
| 商用 J-Link WiFi | 私有协议 | 官方驱动 | 全部 J-Link 生态 | 工业级 | $1380 |
