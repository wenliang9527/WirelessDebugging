# 路由器迁移方案(D 计划,2026-10-26)

> **✅ 终局达成(2026-10-26 晚)**:用户进到 TP-LINK **TL-XDR3010**(=192.168.0.1 有线网关本尊)的管理页,实锤 **AP 隔离=关**、Wi-Fi 多频合一开(2.4G/5G 同名 `SENLO/2` 同密;密码不入仓库,本地凭据文件/密码管理器里)。固件改 SSID 列表 SENLO/2 置顶,重编(COM18 烧录,**读回 md5=40c3ea59 与磁盘一致**——判固件真落地必读回比对,esptool 的 "Hash of data verified" 只证写入瞬间)。首次冷启动 201(NO_AP_FOUND)系时序假象,硬复位后一击连上:**DAP=192.168.0.125**,PC(有线 .111)↔DAP ping 通(均值 13ms),TCP 3240 OPEN,usbip 重挂 + ocdup identify(AT32F403AXG) 全链路恢复。**路由器已做 IP-MAC 绑定**(espressif/AC-A7-04-15-04-FC→.125),复位验证重连仍 .125。热点退役(DAP/OTA 回落保留)。
> **HUAWEI 线彻底废弃**(隔离无管理权);AN-DEWIFI 判定为 PC 里保存的别处网络,本地不存在。

## ⚠️ 2026-10-27 拓扑变化(重要,影响所有网络操作)

家里两台路由是**两台独立设备**(2026-10-26 曾误判同一台):**TL-XDR3010**(SENLO/2,LAN MAC 9c:47:82:58:63:54)与 **TP-LINK_BF5A**(2.4G MAC d0:c7:c0:86:bf:5a)。27 日晨拓扑变动:**0.1 网关角色换到 BF5A**,出网路径 0.1→192.168.1.1 级联;XDR3010 疑似降级 AP,自拿 **192.168.0.110**(80 端口在)。**后果:PC 有线(挂在 0.1/BF5A 域)与 DAP(XDR3010 的 WiFi 客户端)跨域,80-90% 丢包。解法已验证:PC 的 WLAN 直连 SENLO/2(WiFi+网线可并存,上网仍走有线),与 DAP 同 AP 域后全通。**
当前稳定工作路径:**PC WLAN(192.168.0.127)↔ DAP(192.168.0.125)同 AP 直达**;路由器 IP-MAC 绑定(在 XDR3010 上做的)仍然有效,DAP 重启仍拿 .125。以后若再次拓扑变动,先 `arp -a` 看 0.1 的 MAC 是 9c47 还是 d0c7 判断谁在做网关,PC 侧用 `netsh wlan connect name="SENLO/2"` 切同域即可。

- **网络**:DAP STA 连 `SENLO/2` 2.4G BSSID,地址固定 **192.168.0.125**(DHCP 绑定);PC 有线 192.168.0.111 同网直连,无热点依赖
- **固件**:`firmware\esp32s3_v0.4.0_custom\`,SSID 列表 = **SENLO/2 → DAP → OTA**(后两个是外出/回落用,密码 12345678)
- **PC 侧**:`attach_dap_hidden.vbs 192.168.0.125`(以后 IP 不变,可考虑把脚本默认值改成 .125);ocdup 零配置
- **日志口分工**:COM18=USB-Serial-JTAG(esptool 烧录/复位用),COM19=CH343(应用日志 115200);USB 重枚举后可能对调,认设备名不认号
- 已知特性:**首次上电若路由器 2.4G 响应慢会 201 一次后回落热点**,此时点 RST 即连上家网;若嫌烦可日后换 static IP 编译彻底规避

## 1. 新路线

| 路线 | 做法 | 评估 |
| --- | --- | --- |
| **主路线** | 装 ESP-IDF → clone windowsair v0.4.0 源码 → `wifi_cfg.h` 的 SSID 列表里加用户的 WiFi 名+密码 → 编译 S3 → 烧录 → 重跑五层验证 | 固件本体不变(已验证的 Keil/ocdup/usbip 全链路照旧),只改配置;需 ESP-IDF(约 2-3GB,本就在后置任务池) |
| 过渡(可并行) | 手机热点开 SSID `DAP`/`12345678`(频段选 2.4G)→ PC 解放,B/C 测试先跑 | 零工作量,但手机得当热点主机;编译完成后自然淘汰 |

自写代码量:**零**——SSID 列表是固件现成机制(wifi_cfg.h),只填名字密码;其余全是装环境、编译、烧录、按现成流程复测。

## 2. 主路线执行步骤

### 第 1 步:环境(一次性,~2-3GB)
- ESP-IDF **v4.4.2** 离线安装器(官方 Windows installer);S3 目标若报版本不兼容,按仓库 README 提示调整版本(README 写明 ESP32/C3 用 4.4.2,S3 待实测)
- git clone windowsair/wireless-esp8266-dap(GitHub 间歇性抽风,重试即可)

### 第 2 步:改配置(几行)
- `main/wifi_cfg.h`(或同层)的 SSID 数组:加入用户 WiFi 名 + 密码(保留 DAP/OTA 条目,兼容手机热点)
- 其余一概不动(OTA 保持关、GPIO 引脚不变)

### 第 3 步:编译与烧录
- `idf.py set-target esp32s3 && idf.py build`(首次全量约 10-20 分钟)
- esptool 烧录 full 镜像(BOOT+RST 进下载模式,流程与首次烧录相同,文档现成)

### 第 4 步:五层验证(流程现成)
ping → TCP 3240 → usbip 挂载(attach_dap_hidden.vbs 传新 IP)→ ocdup identify+烧录冒烟 → Keil+elaphureLink 一轮

### 第 5 步:收尾
- attach 脚本默认 IP 更新为新地址(建议路由器侧若有 DHCP 就 arp 找,mDNS dap.local 备用)
- 更新各文档记录表与 memory

## 3. 前提确认(编译前必查)

1. 该 WiFi 为 **2.4GHz** 可见(老设备/ESP 能搜到;若只有 5G,固件改了也连不上)
2. 认证方式为**普通 WPA2/WPA3-PSK 密码**(非网页认证的校园/酒店/公司 Portal——Portal 网固件过不了)
3. 密码无特殊字符问题(编译期字符串,一般都行)

## 4. 判定与回退

- 五层验证全过 = 迁移完成,DAP 常驻该 WiFi,PC 重启不再影响它在线
- 编译失败:查 IDF 版本对 S3 的兼容性(README),必要时升/降版本
- 随时可退:重烧 v0.4.0 预编译固件(full.bin 还在 `firmware\esp32s3_v0.4.0\`),回到 Windows/手机热点状态

## 5. 迁移后的新日常

| 场景 | 操作 |
| --- | --- |
