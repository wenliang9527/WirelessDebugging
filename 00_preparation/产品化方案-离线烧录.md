## 2. 架构:三层

```
PC 端 GUI                    调试器固件(ESP32-S3)                目标 MCU
┌──────────────┐   WiFi TCP:1235   ┌──────────────────────┐   SWD
│ 烧录文件页    │ ────上传/管理────▶ │ 存储层:dap_store     │
│ 上传/删除     │   USB console兜底 │  (LittleFS + 索引)    │
│ 切"当前"     │                   │ 引擎层:dap_offline   │ ─────▶ 擦/写/校验
│ 一键烧录+进度 │ ──@FLASH/长按──▶  │  (直调 DAP 底层 SWD)  │
└──────────────┘                   └──────────────────────┘
```

三条通路互相独立:**管理面**(@ 命令,USB console)、**数据面**(TCP:1235 上传)、**执行面**(烧录任务,SWD 直驱)。在线调试(usbip/kcp/elaphureLink)与离线烧录通过 0.8.1 引入的 DAP 互斥锁互斥(§8.2)。

## 4. 文件存储与索引(dap_store)

- **文件系统**:LittleFS(掉电安全——上传中途拔线不损坏分区;esp_littlefs 组件 vendored 进 `components/`,同 led_strip/kcp 先例)。挂载点 `/img`,首次挂载失败自动格式化。
- **命名**:`/img/<slot>.bin`,slot = `0..7`,**上限 8 个文件**(11MB ÷ 8 ≈ 1.3MB/槽,足够覆盖常见 MCU 全片镜像)。
- **索引**:每个 slot 一条元数据,存 NVS 命名空间 `imgstore`(不用索引文件,免掉两处一致性):
  `name`(显示名,上传时指定,≤31 字节)、`size`、`crc32`、`family`(算法家族,如 `PY32`)、`addr`(烧录基址,默认 0x08000000)、`mtime`(上传时间)、`current`(是否当前,恰好一个,删除当前则自动落到最旧的)。
- **CRC32**:上传时 PC 端算好随头帧带上,落盘后板端复算核对;烧录前再核对一次,三保险。

## 5. 命令协议(@ 命令扩展,线格式沿用 dap_cmd.c:`@CMD args` 进,`@OK/@ERR code/@DATA` 出)

| 命令 | 参数 | 应答 | 说明 |
| --- | --- | --- | --- |
| `@FLIST` | — | `@DATA slot=N name=.. size=.. crc=.. family=.. addr=.. mtime=.. cur=0/1`(每 slot 一行,空则仅 `@OK`) | 列出全部文件 |
| `@FSTAT` | `slot=N` | `@DATA` 同上单行 | 单个详情(含最近一次烧录结果) |
| `@FDEL` | `slot=N` | `@OK` / `@ERR` | 删文件+索引;删的是 current 则按 §4 规则回落 |
| `@FSEL` | `slot=N` | `@OK` | 设为当前烧录文件 |
| `@FNAME` | `slot=N name=..` | `@OK` | 改显示名 |
| `@FPUT` | 见下 | `@OK` | USB 兜底上传,分块:`@FPUT begin slot=N name=.. size=.. crc=.. family=.. addr=..` → `@FPUT data <hex>`(≤512B/行)×N → `@FPUT end` |
| `@FLASH` | `slot=N`(缺省=当前) | `@OK started` 后台起任务;进度用 `@FPROG` 轮询 | 触发烧录(烧录中拒绝再次触发) |
| `@FPROG` | — | `@DATA state=idle/running/done/fail slot=.. pct=.. err=..` | 进度/结果查询(GUI 500ms 轮询) |

错误码沿用现有 `@ERR <code> <msg>` 习惯,新增:slot 越界、无当前文件、烧录中忙、文件 CRC 不符、目标连不上、算法不支持。

## 6. WiFi 上传协议(TCP:1235)

帧格式(小端、定长头 + 变长体,风格对齐 uart_bridge 的行协议但走二进制):

| 帧 | 方向 | 体 |
| --- | --- | --- |
| `BEGIN` | PC→板 | slot(u8) name(32B) size(u32) crc32(u32) family(u8) addr(u32) |
| `CHUNK` | PC→板 | seq(u32) + ≤64KB 数据 |
| `ACK` | 板→PC | seq(u32) status(u8)(每 CHUNK 必答,滑窗=1,简单可靠) |
| `FINISH` | PC→板 | —(板端复算 CRC,写索引) |
| `RESULT` | 板→PC | status + msg |

64KB 块直接落盘(写 LittleFS),不占大块 RAM;ACK 后 PC 才发下一块。断线即作废重来(不做续传,§11)。板端服务复用 tcp_server 的 netconn 风格,仅 STA/AP 已联网时监听。

## 7. 离线烧录引擎(dap_offline.c,大头)

- **形态**:独立 FreeRTOS 任务,事件触发(队列:`@FLASH` / GPIO0 长按),**绕过 CMSIS-DAP 命令分发器,直调 `components/DAP` 的 SWD 原语**(DAP.c 的 SWJ 时序/传输函数)。
- **风险探针(半天,D4 第一步)**:先写死一个测试任务直驱 SWD 读目标 IDCODE,验证"绕过分发器直调"这条路,通了再铺开。
- **流程**:SWD connect(DP/AP 初始化)→ halt(DHCSR)→ 擦除 → **RAM flashloader**:把家族算法 loader 写入目标 SRAM,经 DCRSR/DCRDR 喂数据执行页编程 → 回读 CRC 校验 → reset run。
- **家族注册表** `dap_flash_algo.c`:`{ "PY32", loader_bin, loader_src, loader_dst, stack, page_size, ... }`,运行期按索引里的 family 匹配;**PY32 算法直接参考本地 atopenocd-py32 的 flash 驱动源码**(D:\ARMGCCTool\atopenocd-py32)移植。
- **正确性**:写前 CRC(本地文件)+ 写后回读 CRC 双校验;失败给原因码人话(§5)。
- **烧录中 LED**:紫闪=进行中 / 绿 3s=成功 / 红闪=失败(复用 dap_led 状态机,新增三态)。

## 8. 两个关键安全问题

### 8.1 GPIO0 长按不会误进下载模式

BOOT 键(GPIO0)是 strap 脚,但**下载模式只在复位释放瞬间采样**;运行期长按只是普通 GPIO 读。实现:主循环 20ms 轮询,连续 ≥2s 低电平才触发,触发后立刻烧录流程(不复位)。烧录进行中再按无效。

### 8.2 与在线调试互斥

复用 0.8.1 的 DAP 互斥锁:离线任务启动前拿锁,拿不到(在线调试会话进行中)则 `@ERR busy` / LED 黄闪两下放弃;烧录结束释放。反向:在线会话建立时若离线烧录进行中,kcp/usbip 侧同样吃闭门羹(错误提示"离线烧录进行中")。
