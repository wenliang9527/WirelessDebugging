## 已确认

### 2026-10-27 定位变更(重要)

- **产品定位**:从"自家自用"改为 **给同事用 / 开源发布 / 小批量卖几块**
- **两类现有连接方式全部保留**:usbip-win 虚拟 USB(OpenOCD / ocdup / pyOCD)+ elaphureLink TCP 直连(Keil)
- **五条已定约束(2026-10-27 用户拍板)**
  1. **日常保持现有模式**——STA 连路由器,PC 经网络访问,已验收行为不变
  2. **模式只能通过命令切换**——不自动降级、不开自动兜底热点
  3. **OTA 下一步再做**——v1 不碰分区表
  4. **配网要可视化界面、自动搜索、能判断**——扫描列表 + 结果原因可区分
  5. **配网通过 PC 与板子通讯实现**——不做板载网页,不做手机 App
- **两个模式**
  - **STA(默认)**:日常主路径;连不上路由器就按列表重试,永不自作主张
  - **AP(仅 `@MODE AP` 命令进入)**:SSID `DAP-<MAC4>`/`12345678`,板 192.168.4.1,给"没有路由器"的场景
- **配网流程**:PC 上的 Python GUI → USB(COM18) → `@SCAN` 列出周围 WiFi → 选一个填密码 → `@CONNECT` → 成功则存 NVS 并显示 IP;失败按 201/202/204 区分原因
- **配置持久化**:存 NVS;编译期 SSID 列表降级为"出厂默认值"
- **多台并存**:AP 的 SSID 与 mDNS 主机名都带 MAC 后缀,顺带解决原已知风险
- ⚠️ **纯 AP 模式下无法扫描**(IDF 只支持 Station / Station+AP),因此配网固定在 STA 模式,AP 不承担配网职责
