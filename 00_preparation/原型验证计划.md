## 3. 执行步骤

1. **烧固件**:S3 板刷 v0.4.0 的 esp32s3 预编译固件(见固件烧录指南;烧不进按住 BOOT 再上电)
2. **配网**:预编译固件默认以 STA 模式连 SSID **`DAP`/`OTA`(密码 `12345678`),无 AP 模式**——最简单是 PC 开 Windows 移动热点、名称改 `DAP`;连上后 `ping dap.local` 验证设备在线(mDNS)
3. **接线**:按接线参考连目标板 SWD(SWCLK/SWDIO/TVCC/GND 四线起步)
4. **三环境实测**:按测试矩阵逐项跑,记入记录表
5. **结论**:按"判定标准"对比 C3 / S3,更新 `方案对比与选型.md`

## 6. 判定标准(C3 vs S3 选型依据)

- S3 各项达标 → **PCB 直接选 S3**(BOM 只贵几块钱,且原生 USB 可扩展"插线即有线 DAP"双模),C3 对比实验取消
- S3 不达标(掉速/频繁断连)→ 再购 C3(~¥10)对比,定位是芯片问题还是网络环境问题

## 7. 已知风险(测试时留意)

- **mDNS 主机名固定为 `dap.local`**:当前只有一块板无冲突;日后若多台并存,需改固件主机名或用 IP 直连
- **目标板电平**:ESP32 GPIO 非 5V 容忍,TVCC 仅作电平参考;原型阶段选 **3.3V 逻辑**的目标板(PY32/AT32/STM32 常见配置均满足),5V 逻辑目标需电平转换(未来 PCB 再做)
- **ESP32/RISC-V 目标走 JTAG**:与 SWD 四线不同,需接 TDI/TDO(见接线参考);先聚焦 Cortex-M SWD 主线,JTAG 作附加测试
- **Windows 移动热点频段**:老 ESP8266 只支持 2.4G(C3/S3 亦建议热点设 2.4G);另外热点会占用 PC 的 WiFi(有网线的 PC 不受影响)
- 对局域网质量敏感:关掉 DropBox LAN Sync 等广播源再测
- usbip-win 用 v0.3.6-dev/v0.3.5 新版(vhci 已微软认证签名);命令是 `attach` 不是旧文档的 `attach_ude`
- 预编译固件的 WiFi 配置与编译时固件不同,已核实默认 SSID(见固件烧录指南)
- v0.4.0 具体发布日期下载时留意;源码编译 S3 时若 ESP-IDF v4.4.2 报错,查 README 是否对 S3 另有版本要求(README 明确写的是 ESP32/C3 用 4.4.2)
