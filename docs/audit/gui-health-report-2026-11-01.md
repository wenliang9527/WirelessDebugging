## 发现清单

### P2(应修,修复成本可控)

- **P2-1 busy 语义不一致:确认框先弹、动作被静默吞掉**(`dap_gui.py:1785-1793`、`2028-2032`、`2088-2096`)
  `_regen_ap_password`/`_do_delete`/`_do_factory` 都是**先弹 messagebox 确认、再 submit**。
  而 `submit()`(`:1211-1213`)在 busy 时直接丢弃任务,只写一行日志。后果:上一步
  (@CONNECT 最多 32s)没结束时,用户对"恢复出厂设置"点了"确定",**什么都不会发生**,
  结果面板无任何反馈 —— 确认了却没执行,比不确认更糟。连带问题:`_set_buttons`
  (`:1278-1284`)只禁 3 个按钮,扫描/已保存网络页的按钮 busy 期间照常可点。
  修法:把"busy 拦截"提前到确认框之前(入口先查 `_busy` 并在**结果面板**给反馈),
  `_set_buttons` 的禁用面扩到全部会发命令的按钮。

- **P2-2 调试接入页底部安全警告默认不可见**(`dap_gui.py:648-654`,截图证据:mock_tab2)
  四张后端卡片 + 两个 target 行 + 警告条总高超出标签区可用高度(窗口默认 920x760,
  顶部设备卡占掉约 180px),页底那句红字"usbip 与 Keil/OpenOCD 抢同一个 DAP 连接,
  不要同时开"**被窗口下边缘裁掉,且该页无滚动条,拉不到**。这句恰恰是用户最需要
  看到的一句话。修法随布局方案一起解决(压卡片高度 / 警告上移 / 页内滚动)。

- **P2-3 usbip 驱动检查同步跑在 UI 线程**(`dap_gui.py:672-687` + `dap_backends.py:374-402`)
  `driver_installed()` 是同步 `subprocess.run(["pnputil", ...], timeout=20)`。首帧
  `_refresh_backends` 和每次「重新检测」都会在主线程卡 ~300ms;pnputil 异常挂起时
  最长可冻住界面 20 秒。同文件里 `reachable()`/`attached()` 都已后台线程化,这一处
  是漏网之鱼。修法:照 `_usbip_probe_async` 的既有模式后台化 + 事件回投。

- **P2-4 LED 滑块几乎不可见**(截图证据:真机态与 mock 态一致)
  `ttk.Scale`(`:349-352`)在 clam 主题下槽条颜色与白色卡片底色几乎融为一体,
  96px 长的控件在"指示灯"和固件信息之间只剩一道浅痕 —— 用户看不出这是滑块,
  也就不知道亮度可调(这个功能本来是为了回应"灯太刺眼"的真实抱怨)。
  修法:ttk.Style 给 Scale 定制槽色/滑块色,或换成"滑块 + 数值 + 主色描边"的组合。

- **P2-5 无 DPI 感知,默认窗口在 150% 缩放屏上超出屏幕**(`dap_gui.py:93`)
  全代码无任何 SetProcessDpiAwareness 调用(grep 证实)。tk 8.6 在高 DPI 下按
  96 DPI 排版再位图拉伸:文字发虚;且 920x760 逻辑像素在 150% 的 1080p 屏上
  物理高度 1140 > 1080,**默认窗口下边沿出屏**(状态栏看不见)。修法:进程级
  DPI aware(ctypes,标准库)+ 布局尺寸随 DPI 缩放,一起落在美化方案里。

### P3(择机,低成本低风险)

- **P3-1** 顶部状态行/表格的中文在等宽字体里回退渲染(`:311` status_label 用 mono),
  与界面字体不统一 —— 中文段落应用 UI 字体,数字/地址保留 mono。
- **P3-2** `_require_client`(`:2213`)提示"点左上角「刷新」",实际按钮叫「自动探测」
  (配网页那条工具栏才叫「刷新列表」),新用户会对着找不到的按钮找。
- **P3-3** `_send_manual`(`:2165`)所有手动命令一律用 TIMEOUT_CONNECT(32s):
  板子不回话时 busy 长达 32s;按命令前缀给超时(@CONNECT 32s,其余 5s)更好。
- **P3-4** 拔线后 `on_disconnect` 只改徽标不 `_close_client()`(`:1366-1368`),
  后续操作要等 write 失败才暴露;断开时顺手收口并提示"重新探测"更顺。
- **P3-5** `_on_scan_select`(`:1588`)非 OPEN 网络强制 `pass_entry.focus_set()`,
  键盘方向键浏览列表被打断;可改为仅"首次选中"抢焦点或提供选项。
- **P3-6** `_show_done`(`:1638-1663`)给出三段"复制即可用"的命令却没有复制按钮,
  res_hint 只说"下面这段可直接复制";加一个「复制」按钮是顺手的高价值改动。
- **P3-7** `dap_config.py:66-67` 的 `run_list()` 里 `progress` 函数定义后从未调用
  (原单体遗留死代码,属 CLI,顺带删)。
- **P3-8** 字号字面量 `(ui, 10)/(ui, 9)/...` 散布全文,随美化收敛成字号阶梯常量。

### 布局与美观(H 维细节,供视觉稿吸收)

1. 顶部设备卡信息密度合理,但第三行(模式 5 按钮 + 指示灯 + 固件号)单行塞 7 组
   控件,是全窗最挤的一行;minsize 下右侧先被裁。
2. 已保存网络页工具条:5 个按钮 + 右侧统计标签同行,默认宽度下**零余量**,
   minsize(820)下统计标签会被按钮挤压重叠(截图 mock_tab1 已贴边)。
3. 两个 Danger 红按钮(删除选中、恢复出厂设置)并排同权重;「恢复出厂设置」是
   全窗最具破坏性的动作,视觉上却和普通删除一样顺手可点。
4. 日志页(黑底彩色标签)观感最好;配网页表格斑马纹、结果面板富文本层次清晰。
5. 标签页条与卡片衔接处有轻微错缝(tabmargins=(0,6,0,0)),可再收 2-4px。
6. 结果面板大量场景只有 2-3 行文字却占满剩余高度,信息密度低 —— 可考虑把
   "下一步怎么做"做成常驻右栏或收紧高度让表格更高。

## 测试盲区与 selftest 增项建议(实施阶段落)

现有 `_FakeApp` 系断言覆盖:`_show_result`/`_after_show_ap_password`/`_after_regen_ap`
/`_show_ap_hint`/`_sta_summary`/`_on_close`/`_usbip_driver_cached(force)`/`_recheck_usbip`
/`_persist_settings`。建议增补(全部零 GUI 依赖,沿用 #8 写法):

1. busy 时入口拦截必须在**结果面板**给反馈(修 P2-1 后的回归锚);
2. `_set_buttons` 禁用面清单断言(扫一遍全部会发命令的按钮);
3. `_apply_led_value` 边界:pct>20 夹到 20 显示、1 以下忽略;
4. 文案一致性断言:首包格式串("无空格无换行")在 `_show_done`、退避序列
   ("1/2/5/10/15/30")在 `_sta_summary` —— 把这轮人工核对固化成自动核对;
5. `_sort_by` 列切换的方向语义(文本列升序/数值列降序)。
